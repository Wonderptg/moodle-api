# 2026-08-12

## local_aiagentapi: expose native Moodle view functions

- Investigated a Student Shell completion write failure where `POST /api/course-resource/activity/12192/view` returned a Moodle `webservice_access_exception`.
- Root cause: `local_aiagentapi` external service only registered `local_aiagentapi_*` functions, so Moodle rejected official view functions before `page_view()` / resource / quiz view logic could update native completion.
- Added `mod_page_view_page`, `mod_resource_view_resource`, and `mod_quiz_view_quiz` to `public/local/aiagentapi/db/services.php`.
- Updated `scripts/register_aiagentapi_service_functions.php` so the maintenance script also registers those selected Moodle core view functions, not just `local_aiagentapi_*`.
- Bumped `local_aiagentapi` to `2026081200 / 0.3.6`.
- Deployed to `dzexam.cn`, ran Moodle CLI upgrade, re-ran service registration, purged caches, and verified in DB that all three functions exist and are linked to service id 6 (`local_aiagentapi`).
- Follow-up caveat: Moodle's official `mod_*_view_*` functions take module instance ids (`pageid`, `resourceid`, `quizid`), so any Next adapter route starting from a `cmid` must resolve `cm.instance` before calling them.
